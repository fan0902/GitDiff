# GitDiff 公开仓库净化与发布设计

日期：2026-07-22

## 目标

把当前可运行的 GitDiff 源码安全发布到公开仓库 `fan0902/GitDiff`，同时满足：

- 公开内容不包含本机用户名、本机绝对路径或内部项目路径。
- 公开内容不包含任何特定内部浏览器或内部产品信息。
- GitDiff 仍优先使用 macOS 默认浏览器，并尽可能复用已有 `localhost:9002` 标签。
- 不上传当前开发提交历史、内部设计文档、执行计划或临时工作文件。
- 发布后从远端重新检查文件树与内容。

## 已确认决策

- 目标仓库是公开且当前为空的 GitHub 仓库。
- 远端只创建一个全新的根提交，并将其作为 `main`。
- 不创建 Pull Request。
- 浏览器逻辑不写死任何浏览器名称，运行时动态识别 macOS 默认浏览器。
- 本次只发布 Git 源码，不使用 Sites 托管部署。

## 路径与仓库选择

页面首次启动时不再内置任何默认仓库路径。客户端只从浏览器本地存储读取上次成功加载的仓库路径；没有历史记录时输入框为空。

macOS 启动器通过 AppleScript 的用户域 Library 路径动态构造：

- `Application Support/GitDiff/site`
- `Application Support/GitDiff/GitDiff.pid`
- `Application Support/GitDiff/GitDiff.log`

启动命令通过一组通用 Node 搜索路径调用 `node`，不包含用户名或某台机器的 Home 路径。

## 默认浏览器优先

新增独立 JXA 脚本，通过 AppKit 的 `NSWorkspace` 查询 `http://localhost:9002` 的默认处理应用。

执行顺序：

1. 获取当前默认浏览器应用。
2. 如果应用已运行且暴露可读的窗口与标签接口，遍历其中的标签。
3. 找到 URL 以 `http://localhost:9002` 开头的标签后，选中、刷新并激活默认浏览器。
4. 没有匹配标签，或默认浏览器不支持标签控制时，调用系统 URL 打开能力，由默认浏览器打开页面。

脚本不枚举、不回退到其他非默认浏览器。浏览器控制失败不影响 GitDiff 本地服务运行。

## 公开树范围

公开根提交包含运行、构建、测试和 macOS 打包所需源码：

- 应用页面与样式
- 只读 Git API
- 本地启动脚本
- macOS 启动器、图标和构建脚本
- 测试、配置、锁文件与 README

公开根提交排除：

- `.git` 与既有提交历史
- `.superpowers/`
- `docs/superpowers/`
- `node_modules/`、构建输出和运行日志
- worktree 元数据
- 任何本机生成的环境文件

## 发布前审计

发布前对即将生成的公开树执行两类审计：

1. 内容扫描：本机用户名、用户目录绝对路径、内部仓库名称、内部域名和特定内部浏览器名称均不得出现。
2. 文件范围扫描：只允许预期的产品源码、配置、资源和测试文件，不允许内部设计文档或临时目录。

同时运行完整构建、测试、lint 和 AppleScript/JXA 语法检查。任何一项失败都停止 push。

## 发布策略

在本地净化分支完成并验证改动后，从净化后的文件树创建一个无父提交的根提交。将该提交直接推送为远端 `main`。这种方式不会把当前本地分支的历史带到公开仓库。

远端仓库为空，因此不需要覆盖既有提交。若 push 前发现远端出现提交，停止并重新确认，不使用强制推送。

## 发布后验证

push 成功后：

- 读取远端默认分支与 HEAD。
- 使用一个新的临时 clone 获取公开仓库。
- 在 clone 中重新执行敏感内容扫描。
- 确认历史只有一个根提交。
- 确认 README、应用源码、只读 Git API、浏览器脚本和测试均存在。

## 非目标

- 不发布 Sites URL。
- 不上传 GitDiff.app 二进制安装包。
- 不修改所选业务仓库。
- 不创建 PR、Release 或 GitHub Actions 工作流。
- 不修改 GitDiff 的 9002 页面端口和 3101 API 端口。
