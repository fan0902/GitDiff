# 提交关系图分支标签设计

日期：2026-08-12

## 目标

在提交关系图中直接展示真实指向某个提交的分支名称，例如 `master`、`origin/master`，让用户无需根据“基准分支 HEAD”推断线上分支位置。

## Git 语义

- 分支名只标在它当前直接指向的提交上，不标到所有祖先提交。
- 本地分支和远端跟踪分支均可展示，保留完整名称以区分 `master` 与 `origin/master`。
- 数据来自本地仓库当前 refs。GitDiff 继续保持只读且不执行 `fetch`，因此 `origin/master` 表示本地已知的远端跟踪状态，不承诺等同于远端服务器此刻状态。
- 标签只覆盖当前图中可见的真实提交；折叠节点不承载分支名。

## 数据读取

提交图 API 新增一次只读 `git for-each-ref` 调用，读取：

- `refs/heads/*`
- `refs/remotes/*`

忽略远端符号引用 `*/HEAD`。结果按提交 SHA 分组，并写入每个图节点的 `refs: string[]`。名称排序遵循：

1. 当前基准分支名称。
2. 当前目标分支名称。
3. 本地分支按名称。
4. 远端跟踪分支按名称。

同一名称不重复。

## 节点展示

- 有分支指针的提交在卡片顶部 SHA 旁展示一个紧凑分支徽标。
- 优先显示排序后的第一个名称，例如 `master`。
- 超过一个名称时追加 `+N`，避免提交卡片变宽或变高。
- 徽标的原生 `title` 与无障碍名称包含该节点全部分支名；鼠标悬停可查看完整列表。
- 节点详情面板新增“指向此提交的分支”，逐项展示全部名称。

## 固定泳道标签

现有泳道标题位于横向画布内部，滚动后会离开视口。改为在滚动容器左侧叠加固定标签：

- `基准 · <base>`
- `共同历史`
- `目标 · <target>`

标签仅作导航提示，不遮挡提交节点和连线，不改变横向滚动语义。小屏幕保持同样位置。

## 特殊情况

- 基准和目标指向同一提交时，该节点可以同时展示两边分支名。
- 分支名很长时，节点只显示省略后的首个徽标，悬停与详情仍展示完整名称。
- 指定提交位于当前分支对之外时，也展示直接指向它的本地 refs（如有）。
- 没有任何分支直接指向某提交时，不显示空徽标或空详情区。

## 验证

- 图 API 能将本地 `master` 和 `origin/master` 映射到正确提交。
- 远端 `origin/HEAD` 不进入标签。
- 多个 refs 的排序稳定，且保留完整名称。
- 节点只显示首个标签与 `+N`，完整列表可通过悬停和详情查看。
- 横向滚动时泳道标签保持可见。
- Git 服务仍通过只读命令安全测试。
- 运行 lint、构建和完整测试，并部署本机 GitDiff App 验证真实仓库数据。
