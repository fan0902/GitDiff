# 默认分支列表排序设计

日期：2026-07-29

## 目标

目标分支下拉列表在未输入搜索词时优先展示开发主分支，并让其余分支按最后提交时间从近到远排列，方便快速选择最近活跃的分支。

## 排序规则

未输入搜索词时依次应用以下规则：

1. 存在本地 `dev` 时，将它固定在第一位。
2. 不存在本地 `dev`、但存在 `origin/dev` 时，将 `origin/dev` 固定在第一位。
3. 除置顶分支外，其余分支按 `updatedAt` 从新到旧排列。
4. 时间相同或无法解析时保持 Git API 返回的原始相对顺序。
5. 如果两种 dev 分支都不存在，所有分支直接按时间从新到旧排列。

输入搜索词后不应用上述置顶规则，继续使用现有模糊匹配分数排序。

## 实现

新增纯函数模块 `app/branch-order.ts`，输入只需要分支的 `name` 和 `updatedAt`，输出新的排序数组，不修改原数组。`SearchableBranchSelect` 在搜索词为空时调用该函数；有搜索词时保留现有匹配逻辑。

后端已经通过 `for-each-ref --sort=-committerdate` 返回时间信息，本次不增加 Git 命令或写操作。前端仍显式比较 `updatedAt`，使排序规则可独立验证，不依赖后端返回顺序。

## 验证

- 本地 `dev` 优先于更新的普通分支。
- 缺少本地 `dev` 时，`origin/dev` 置顶。
- 两种 dev 同时存在时只置顶本地 `dev`，`origin/dev` 参与普通时间排序。
- 无 dev 分支时全部按时间从新到旧排列。
- 相同或无效时间保持原始相对顺序。
- 搜索状态仍使用模糊匹配排序。
