# GitDiff 完整源码对照设计

日期：2026-07-29

## 目标

让用户在审阅文件差异时直接看到基准分支和目标分支的完整源码，而不是只看到 Git diff 每个改动块前后的 3 行上下文。完整源码视图不使用展开箭头、折叠占位或上下文行数设置。

## 问题

当前本地 API 使用 `git diff --unified=3`。蓝色 `@@ ... @@` 行表示两个改动块之间存在被省略的源码，但客户端没有收到这些行，因此无法展示用户希望阅读的原分支既有实现。

## 已确认决策

- 默认审阅模式改为“完整对照”。
- 左栏展示基准分支完整源码，右栏展示目标分支完整源码。
- 两栏使用同一纵向滚动区域，并按 diff 行对齐。
- 未修改代码始终展示，不提供折叠或展开控件。
- 新增代码使用浅绿色，删除代码使用浅红色，缺失的对应行使用淡灰色。
- 每栏顶部固定显示分支角色和分支名，避免把原代码与目标代码混淆。
- 保留“仅看改动”作为辅助模式，复用当前紧凑 diff。
- 统一视图不再作为主要入口；完整对照是默认模式。

## 信息架构

文件卡片中的模式切换调整为：

1. 完整对照
2. 仅看改动

完整对照顶部增加双栏标题：

- `基准源码 · <base>`
- `目标源码 · <target>`

双栏标题在文件代码区域纵向滚动时保持可见。文件标题、语言、路径、增删统计和“标为已读”继续复用现有结构。

## 完整源码数据

新增只读接口：

```text
POST /api/full-diff
```

请求沿用文件差异接口字段：

```json
{
  "repoPath": "/absolute/repository/path",
  "base": "origin/master",
  "target": "feat/example",
  "path": "app/example.py",
  "oldPath": "app/old-example.py"
}
```

服务端解析 base、target 和共同祖先，继续保持当前三点比较语义。它返回覆盖整个文件的 unified diff，而不是只保留 3 行上下文。客户端继续使用现有 diff 解析和左右对齐逻辑，不单独拼接两个文件，避免重命名、新增、删除和无换行结尾等情况产生不一致。

响应：

```json
{
  "diff": "...",
  "truncated": false
}
```

现有 `/api/diff` 保持 `--unified=3`，供“仅看改动”模式使用。

## 渲染规则

- 完整对照隐藏 `diff --git`、`index`、文件头和 `@@` 等内部元数据。
- 所有 context 行在左右两侧同时展示。
- 连续 deleted/added 行按现有算法成对排列；数量不等时，较短一侧显示淡灰空白行。
- 新增文件左侧全部为空，删除文件右侧全部为空。
- 重命名文件继续用 `oldPath` 读取基准侧内容。
- 横向内容保持同步滚动，长行不自动折行，避免破坏左右行对齐。
- 行号固定在各自代码栏左侧，分别使用原文件行号和目标文件行号。

## 大文件与失败处理

- 单文件响应继续受服务端字节上限保护。
- 超过上限时显示明确提示，并允许用户切换到“仅看改动”。
- 二进制文件继续只展示变化提示。
- 文件只有模式或元数据变化时，不伪造源码差异。
- 切换文件或分支时清除上一文件的完整 diff，避免短暂显示错误内容。

## 可访问性与响应式

- 模式切换使用具有选中状态的按钮，并提供清晰文字标签。
- 双栏标题不能只依赖颜色区分，必须包含“基准源码”和“目标源码”。
- 窄屏仍保持左右语义，通过横向滚动阅读，不把两栏改为上下排列。
- 代码区域支持键盘滚动，颜色对比满足现有主题的可读性。

## 验收场景

- 修改文件的两个改动块之间有大量未修改源码，完整对照中全部连续可见。
- 截图所示 `@@ -268,6 +281,18 @@` 位置不再形成不可读的省略区域。
- 基准分支旧实现稳定显示在左侧，目标分支对应实现显示在右侧。
- 新增文件、删除文件、重命名文件正确对齐。
- 左右增删行数量不同时空白侧正确补位。
- 切换到“仅看改动”仍显示当前紧凑 diff。
- 大文件、二进制文件和无文本差异文件有清晰提示。
- 重新比较分支或切换文件后不显示上一次请求的数据。

## 非目标

- 不提供逐段展开箭头。
- 不提供上下文行数滑块或设置项。
- 不做代码编辑、评论或暂存操作。
- 不修改仓库工作区、分支或提交。
- 不在本次改动中引入语法高亮或代码搜索。
