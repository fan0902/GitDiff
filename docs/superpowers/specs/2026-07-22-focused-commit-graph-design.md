# GitDiff 聚焦提交关系图设计

日期：2026-07-22

## 目标

在 GitDiff 中增加一个用于排查分支关系的“提交关系”视图。它围绕当前基准分支、目标分支和一个可选的指定提交，清晰回答：

- 两个分支最后在哪里共享历史？
- 它们从哪里分叉？
- 指定提交位于共同历史、基准侧、目标侧，还是与当前分支对无关？
- 每侧有哪些关键独有提交？

视图保持只读、聚焦和可解释，不替代完整的 Git 历史浏览器。

## 已确认决策

- 采用“聚焦排查”范围，不默认展示完整仓库历史。
- 复用当前基准分支和目标分支选择。
- 支持输入一个可选 commit SHA 定位。
- 关键备注由系统自动生成，不提供手工备注。
- 采用横向诊断地图：共同历史在左，分叉点居中，基准分支在右上，目标分支在右下。
- 提交过多时折叠，不使用无限画布。

## 信息架构

GitDiff 主工作区增加两个并列视图：

1. 文件差异
2. 提交关系

仓库路径、基准分支和目标分支是两个视图共享的上下文。切换视图不重新加载仓库。提交关系视图额外提供：

- 可选 commit SHA 输入框
- “定位提交”按钮
- 关系摘要
- 横向提交图
- 提交详情面板

## 聚焦范围

默认图包含：

- 基准分支 HEAD
- 目标分支 HEAD
- 两个 HEAD 回溯到共同祖先的路径
- 分叉点之前 3 个共同祖先
- 每侧最多 12 个独有提交

超过限制的连续提交压缩为“省略 N 个提交”节点。折叠节点保留边关系与所属泳道，但不加载被折叠提交的详情。

如果指定提交不在默认图中：

- 如果它是任一分支的祖先，扩展从该提交到当前图的最短祖先路径并纳入图中。
- 如果提交存在但不是两个分支任一侧的祖先，在图外提示区展示该提交，并标注“与当前分支对无祖先关系”。
- 如果 SHA 不存在，只在输入区域显示错误，当前图保持可用。

## 横向诊断地图

地图从左向右表示由旧到新的提交方向：

- 左侧单泳道：共同历史
- 中部关键节点：共同祖先/分叉点
- 右上泳道：基准分支独有历史
- 右下泳道：目标分支独有历史

普通提交使用小型中性节点。以下节点使用更高视觉权重：

- 基准分支 HEAD
- 目标分支 HEAD
- 共同祖先/分叉点
- 指定提交
- merge commit
- 折叠节点

图形优先适配工作区宽度。内容超过可用宽度时使用横向滚动，不提供自由拖拽或任意缩放。小屏幕保持同一布局方向，避免改变关系语义。

## 自动备注

备注只出现在关键位置，避免每个节点都带说明。系统可生成：

- `基准分支 HEAD`
- `目标分支 HEAD`
- `共同祖先 · 两个分支最后共有的提交`
- `分叉点`
- `指定提交 · 位于共同历史`
- `指定提交 · 仅位于基准分支`
- `指定提交 · 仅位于目标分支`
- `Merge commit · 包含 N 个父提交`
- `省略 N 个提交`
- `与当前分支对无祖先关系`

关系摘要在图上方展示 ahead/behind 数量、共同祖先短 SHA、指定提交归属和历史完整性提示。

## 提交详情

点击提交节点后，从右侧打开轻量详情面板，展示：

- 短 SHA 和完整 SHA
- 提交标题
- 作者与提交时间
- 所属范围：共同、仅基准、仅目标或无关
- 父提交列表
- 相对分叉点的位置
- 自动备注
- “复制 SHA”操作

按 Escape 或点击关闭按钮收起面板。节点支持键盘聚焦和 Enter 打开。

## 本地 API

新增只读接口：

```text
POST /api/graph
```

请求：

```json
{
  "repoPath": "/absolute/repository/path",
  "base": "origin/master",
  "target": "feat/member-material-0722",
  "focusCommit": "dc93ee6"
}
```

`focusCommit` 可省略。API 继续使用已有仓库路径校验和 commit 解析规则。

响应核心结构：

```json
{
  "base": { "name": "origin/master", "sha": "..." },
  "target": { "name": "feat/member-material-0722", "sha": "..." },
  "mergeBase": "...",
  "ahead": 1,
  "behind": 0,
  "historyComplete": true,
  "nodes": [
    {
      "sha": "...",
      "shortSha": "dc93ee6",
      "parents": ["..."],
      "subject": "feat: support locales_mobile",
      "author": "...",
      "authoredAt": "...",
      "scope": "target",
      "kind": "focus",
      "annotation": "指定提交 · 仅位于目标分支"
    }
  ],
  "focus": { "sha": "...", "relation": "target" }
}
```

`scope` 取值为 `common`、`base`、`target` 或 `unrelated`。`kind` 用于表达 `commit`、`head`、`merge-base`、`focus`、`merge` 或 `collapsed`。
折叠段也放在 `nodes` 中：其 `kind` 为 `collapsed`，使用稳定的合成 `id` 代替 `sha`，并携带 `collapsedCount`、`scope` 和相邻节点引用。普通提交节点始终携带真实 `sha`。

## Git 数据读取

API 只调用读取命令：

- `git rev-parse --verify`
- `git merge-base`
- `git merge-base --is-ancestor`
- `git rev-list --parents --topo-order --date-order`
- `git show --no-patch --format=...`

API 不执行 checkout、switch、fetch、merge、rebase、commit、push 或文件写入。

服务端负责：

- 引用和 SHA 校验
- 共同祖先计算
- 分支归属判断
- 聚焦范围裁剪
- 折叠节点生成
- 自动备注生成

客户端负责：

- 固定泳道布局
- 节点和边绘制
- 横向滚动
- 节点选择与详情面板
- 键盘交互

## 特殊情况

### 没有共同祖先

分别展示两棵短树，中央使用断开标记，并显示“两个分支没有共同历史”。不伪造分叉点。

### 没有分叉

如果目标分支没有独有提交，使用单线历史并标注“目标分支未产生独有提交”。基准分支同理。

### 浅克隆或历史缺失

当 Git 无法得到预期祖先、检测到 shallow repository，或回溯在边界中断时，`historyComplete=false`。页面提示“本地历史可能不完整”，不推断缺失关系。

### 多父提交

merge commit 显示主线父边和次级父边，并自动备注父提交数量。聚焦图只展开通往当前基准、目标和指定提交的相关父边。

### 无效指定提交

返回可区分的输入错误。页面保留上一次成功的图，仅在 SHA 输入处显示错误。

## 可访问性与响应式

- 所有提交节点均可键盘聚焦。
- 节点使用可读标签描述 SHA、提交标题和关系。
- 颜色不作为唯一信息编码；泳道、节点形状、标签和文字共同表达关系。
- 详情面板打开时焦点进入面板，关闭后返回原节点。
- 小屏幕使用横向滚动，并固定关键备注的最小可读字号。

## 验收场景

- 普通分叉，目标分支领先。
- 基准分支领先。
- 两侧均有独有提交。
- 指定提交位于共同历史。
- 指定提交仅位于基准侧。
- 指定提交仅位于目标侧。
- 指定提交与当前分支对无关。
- merge commit 包含两个或更多父提交。
- 两个分支没有共同祖先。
- 两个分支无内容分叉。
- SHA 不存在。
- 浅克隆导致历史不完整。
- 超过每侧 12 个独有提交时正确折叠。
- 键盘选择节点、打开和关闭详情面板。
- 小屏幕横向滚动且关键备注可读。

## 非目标

- 不展示整个仓库的无限提交历史。
- 不支持任意数量分支同时绘制。
- 不执行 fetch 或补全浅克隆历史。
- 不修改分支、标签或提交。
- 不提供手工备注或持久化注释。
- 不提供交互式 rebase、cherry-pick、merge 或 reset。
