# GitDiff 变更块连续导航设计

日期：2026-07-29

## 目标

让用户在完整源码对照中快速浏览一个文件内的多处变更，不再通过滚动条手工寻找下一段新增、删除或修改代码。

## 已确认决策

- 导航单位是“连续变更块”，不是单行。
- 导航器放在右侧“目标源码”标题栏中，并随代码区域滚动保持可见。
- 导航器展示当前位置和总数，例如 `变更 3 / 12`。
- 提供“上一处”和“下一处”两个文字按钮，不使用含义不清的展开箭头。
- 打开文件后自动定位到第一处变更。
- 到达最后一处后继续“下一处”会回到第一处；“上一处”同样循环。
- 完整对照和仅看改动两种模式使用相同导航规则。
- 当前变更块使用轻量强调，不覆盖现有新增绿色和删除红色。

## 变更块定义

客户端基于已经对齐的 `SplitRow[]` 计算导航块：

- `left.kind === "deleted"` 或 `right.kind === "added"` 的代码行属于变更。
- 相邻的变更代码行合并为同一个变更块。
- 两个变更块之间只要出现一行普通 context，就视为两个块。
- 紧凑模式中的 hunk/meta 行不计入变更块，也会中断相邻关系。
- 纯删除变更虽然右栏为空，仍在右侧对应的空白行建立导航锚点。
- 文件没有文本变更、文件过大或为二进制时不展示导航器。

每个代码行在渲染前获得可选的 `changeIndex`。同一变更块的所有行使用同一个从 0 开始的索引。

## 导航交互

导航器位于目标源码标题栏右侧：

```text
目标源码  <target branch>        变更 3 / 12   上一处   下一处
```

行为如下：

1. 文件差异加载完成后，将当前索引设为第一处并自动滚动到第一处变更。
2. 点击“下一处”计算 `(current + 1) % count`。
3. 点击“上一处”计算 `(current - 1 + count) % count`。
4. 目标变更块滚动到代码容器顶部标题栏下方，并保留少量上文。
5. 用户切换文件、分支或显示模式时，重新计算变更块并定位第一处。
6. 只有一个变更块时仍显示 `1 / 1`，两个按钮都会回到该块，交互保持一致。

滚动默认使用平滑动画；当系统启用 `prefers-reduced-motion: reduce` 时使用即时滚动。

## 当前变更强调

- 当前变更块的左右两栏增加细窄的强调边线和轻微内阴影。
- 新增、删除、context 和空白行的原背景色保持不变。
- 强调覆盖整个连续块，不只强调首行。
- 强调色不能作为唯一状态表达；导航器中的 `当前位置 / 总数` 同时提供文字信息。

## 状态与 DOM 边界

客户端新增：

- `currentChangeIndex`：当前变更块索引。
- `sourceCompareRef`：完整代码滚动容器。
- 变更块标注结果：由 `splitRows` 派生，不重复存储。

每个变更块首行输出稳定属性 `data-change-index="N"`，其余同行只携带视觉状态。跳转时只在当前 `sourceCompareRef` 内查找对应锚点，不查询页面其他文件或全局 DOM。

## 特殊情况

### 请求尚未完成

不展示导航器，也不执行自动滚动。新请求发起时立即清除旧索引。

### 完整源码被截断

完整模式不展示导航器；用户切换到可用的“仅看改动”后按紧凑 diff 重新生成导航。

### 模式切换

完整模式与紧凑模式的行结构不同，因此模式切换后总数和锚点都重新计算，并回到第一处。

### 用户手工滚动

第一版不根据滚动位置反向更新当前位置，避免引入滚动监听、抖动和复杂状态。当前位置只由自动首次定位和上下处按钮控制。

## 可访问性

- 导航器使用 `aria-label="代码变更导航"`。
- 按钮提供完整的 `aria-label`，包含目标位置，例如“下一处变更，前往第 4 处，共 12 处”。
- 当前位置使用可读文本，不依赖按钮图标或颜色。
- 自动滚动后不强制夺取键盘焦点，避免打断按钮连续操作。

## 验收场景

- 一个文件有多行连续新增时只计为一处。
- 两段变更之间有普通源码时计为两处。
- 修改块同时包含删除和新增时只计为一处。
- 纯删除块可以跳转到右侧对应空白区域。
- 点击下一处和上一处可以循环导航。
- 打开文件、切换文件、切换分支和切换模式后自动定位第一处。
- 当前块有轻量强调，红绿背景保持可辨认。
- 二进制、无文本差异、请求中和截断状态不展示导航。
- 减少动态效果模式下不使用平滑滚动。

## 非目标

- 不增加滚动条缩略图或变更分布地图。
- 不增加展开/折叠代码能力。
- 不增加快捷键或用户设置。
- 不根据手工滚动实时推断当前变更块。
- 不改变 Git diff API 或文件比较语义。
